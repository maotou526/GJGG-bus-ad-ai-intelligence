> 最后更新：2026-02-08

## 一、概述

### 1.1 迁移策略

采用 **混合式迁移策略 (Hybrid Migration Strategy)**：
- **核心框架**：全面转向 Vue 3 (Script Setup) + TypeScript + Element Plus
- **流程设计器**：保留原 `lr-workflow-ui.js` 图形引擎，Vue 组件封装
- **属性面板**：完全重写为 Vue 组件
- **业务表单**：使用 Vue 组件动态加载

### 1.2 技术栈

| 类别 | 技术 |
|------|------|
| 前端框架 | Vue 3.x (Composition API) |
| 开发语言 | TypeScript |
| UI 组件库 | Element Plus |
| 状态管理 | Pinia |
| 遗留兼容 | jQuery 3.6.0（仅限画布渲染） |

## 三、核心组件详解

### 3.1 流程设计器 (Designer)

**文件**: `components/Designer/index.vue`

**策略**: Vue Wrapper 封装 jQuery 图形引擎

**实现要点**:
1. `onMounted` 中动态注入 jQuery 和 `lr-workflow-ui.js`
2. 初始化 `#lr_workflow_container` 画布
3. 通过 `dfop` 配置对象传递数据
4. 调用 `$.lrworkflow.render()` 渲染流程图

**数据流**:
```
加载: API 获取 JSON → dfop 配置 → $.lrworkflow.render()
保存: container.lrworkflowGet() → JSON → API 更新
```

**事件钩子**:
```javascript
dfop: {
  openNode: (node) => {
    // 双击节点时打开属性面板
    propertyPanelRef.value.open(node)
  },
  openLine: (line) => {
    // 双击连线时打开连线属性弹窗
    lineDialogRef.value.open(line)
  }
}
```

## 八、业务表单组件规范

本章节定义了工作流业务表单组件的开发规范，确保表单组件与审批容器（`work/index.vue`）能够正确交互。

### 8.1 架构概述

```
┌─────────────────────────────────────────────────────────────┐
│                    work/index.vue (审批容器)                  │
├─────────────────────────────────┬───────────────────────────┤
│         左侧 - 业务表单区         │      右侧 - 审批控制区      │
│  ┌─────────────────────────┐   │  ┌─────────────────────┐  │
│  │   动态加载的表单组件       │   │  │    审批意见输入      │  │
│  │   (通过 FormRegistry)    │   │  │    操作按钮区        │  │
│  │                         │   │  │    流转记录         │  │
│  │   ← formRef 引用 →      │   │  └─────────────────────┘  │
│  └─────────────────────────┘   │                           │
└─────────────────────────────────┴───────────────────────────┘
```

**核心问题**：审批按钮在容器中，但审核员可能需要在表单中填写/修改内容。点击审批按钮时，需要：
1. 触发表单验证
2. 获取/保存表单数据
3. 执行审批操作

**解决方案**：通过 `defineExpose` 暴露标准接口，实现容器与表单的双向通信。

### 8.2 表单组件 Props 规范

所有业务表单组件**必须**接收以下 Props：

```typescript
interface WorkflowFormProps {
  /** 是否只读模式（查看模式时为 true） */
  readonly: boolean

  /** 初始表单数据（从流程 FormData 字段解析） */
  data: Record<string, any>

  /** 当前节点 ID */
  nodeId: string

  /** 表单参数（包含 URL 参数和 processId） */
  formParams: {
    id: string           // processId，也是业务数据主键
    [key: string]: any   // 其他 URL 参数
  }

  /** 当前节点配置的按钮列表 */
  buttons: WorkflowButton[]
}
```

### 8.3 按钮数据结构

节点配置的按钮通过 `btnList` 字段传递：

```typescript
interface WorkflowButton {
  id: string           // 按钮 ID（自动生成的 GUID）
  name: string         // 按钮名称（如：同意、不同意、驳回）
  code: string         // 按钮编码（如：agree、disagree、reject）
  isHide: '1' | '2'    // 是否隐藏（'1'=隐藏, '2'=显示）
  isSign: '1' | '2'    // 是否需要签名/盖章（'1'=需要, '2'=不需要）
  next: '1' | '2'      // 下一节点审核人（'1'=不能手动设置, '2'=能手动设置）
}
```

**常用按钮编码**：

| code | name | 说明 |
|------|------|------|
| `agree` | 同意 | 审核通过，流转到下一节点 |
| `disagree` | 不同意 | 审核不通过，流程可能终止或退回 |
| `reject` | 驳回 | 驳回到上一步或指定节点 |
| `next` | 下一步 | 流转到下一步（非审批场景） |
| `transfer` | 转办 | 转给其他人处理 |
| `cancel` | 作废 | 作废整个流程 |
| `save` | 保存 | 保存草稿，不流转 |
| `recall` | 撤回 | 撤回已提交的申请 |

### 8.4 表单组件 Expose 接口规范

所有业务表单组件**必须**通过 `defineExpose` 暴露以下方法：

```typescript
interface WorkflowFormExpose {
  // ========== 必须实现 ==========

  /**
   * 验证表单
   * @returns 验证是否通过
   */
  validate(): Promise<boolean>

  /**
   * 获取表单数据
   * @returns 表单数据对象，将随审批请求提交到后端
   */
  getFormData(): Promise<Record<string, any>>

  // ========== 可选实现 ==========

  /**
   * 保存表单数据到后端
   * @returns 保存是否成功
   */
  save?(): Promise<boolean>

  /**
   * 审批前钩子（在确认对话框之前调用）
   * @param operationCode 操作码（如 agree、disagree）
   * @param operationName 操作名称（如 同意、不同意）
   * @returns 返回 false 将阻止审批继续
   */
  onBeforeAudit?(operationCode: string, operationName: string): Promise<boolean>

  /**
   * 审批后钩子
   * @param operationCode 操作码（如 agree、disagree）
   * @param operationName 操作名称（如 同意、不同意）
   * @param success 审批是否成功
   */
  onAfterAudit?(operationCode: string, operationName: string, success: boolean): void

  /**
   * 按钮点击处理（用于自定义按钮行为）
   * @param button 被点击的按钮
   * @returns 返回 true 表示已处理，容器不再执行默认行为
   */
  onButtonClick?(button: WorkflowButton): Promise<boolean>
}
```

### 8.5 按钮渲染机制

#### 8.5.1 按钮来源

按钮配置来自流程设计器中节点的 `btnList` 属性。在流程设计时，管理员可以为每个审批节点配置不同的按钮。

#### 8.5.2 渲染位置

按钮有两种可能的渲染位置：

| 位置 | 说明 | 适用场景 |
|------|------|----------|
| **容器右侧面板** | 默认位置，由 `work/index.vue` 渲染 | 标准审批按钮（同意/不同意） |

### 8.6 审批流程时序

> **实现说明**：采用力软（Learun）模式，审批成功后再保存表单数据。这种设计确保只有审批通过后才更新业务数据。

```
用户点击审批按钮（如"同意"）
       ↓
┌──────────────────────────────────┐
│ 1. 前置检查                       │
│    - 特定按钮（如不同意）检查意见   │
└──────────────────────────────────┘
       ↓
┌──────────────────────────────────┐
│ 2. formRef.validate()            │  ← 表单验证（如有表单）
│    - 失败：提示错误，中止         │
│    - 通过：继续                   │
└──────────────────────────────────┘
       ↓
┌──────────────────────────────────┐
│ 3. formRef.onBeforeAudit?()      │  ← 审批前钩子（可选）
│    - 返回 false：中止             │
│    - 返回 true/undefined：继续    │
└──────────────────────────────────┘
       ↓
┌──────────────────────────────────┐
│ 4. 用户确认对话框                 │  ← "确定要XX此流程吗？"
│    - 取消：中止                   │
│    - 确定：继续                   │
└──────────────────────────────────┘
       ↓
┌──────────────────────────────────┐
│ 5. AuditFlow API 调用            │  ← 提交审批（先审批）
│    {                             │
│      processId, taskId,          │
│      operationCode, operationName│
│      des: 审批意见                │
│    }                             │
│    - 失败：提示错误，调用          │
│            onAfterAudit(code,false)│
│    - 成功：继续                   │
└──────────────────────────────────┘
       ↓
┌──────────────────────────────────┐
│ 6. formRef.save?()               │  ← 保存表单（审批成功后）
│    - 如有 save 方法则调用         │
│    - 保存失败仅警告，不阻断流程    │
└──────────────────────────────────┘
       ↓
┌──────────────────────────────────┐
│ 7. formRef.onAfterAudit?()       │  ← 审批后钩子（可选）
│    onAfterAudit(code, true)      │
└──────────────────────────────────┘
       ↓
     完成，返回列表页
```

**关于事务性说明**：

当前实现采用力软的模式，审批和表单保存是两个独立的 API 请求。这意味着：
- 审批成功 + 表单保存成功：正常情况
- 审批成功 + 表单保存失败：审批已完成，表单数据未保存（会警告用户）
- 审批失败：表单不会保存

如需真正的事务性保证（两者同时成功或同时失败），需要后端提供统一的审批+保存接口。

### 8.7 特殊场景处理

| 场景 | 处理方式 |
|------|----------|
| 节点未配置表单 | 跳过表单验证和保存，直接审批 |
| 节点未配置按钮 | 使用默认按钮（同意、不同意） |
| 只读模式（查看） | 不调用 validate/save，审批按钮区不显示 |
| 表单验证失败 | 阻止审批，提示"表单验证未通过" |
| onBeforeAudit 返回 false | 阻止审批，由表单组件自行处理 |
| 审批 API 失败 | 调用 onAfterAudit(code, name, false) 通知表单 |
| 表单保存失败 | 审批已完成，仅警告用户表单保存失败 |
| 按钮配置 isHide='1' | 不渲染该按钮 |
| 按钮配置 isSign='1' | 审批前弹出签名/盖章组件（待实现） |
| 不同意操作无意见 | 阻止审批，提示"请输入拒绝理由" |

### 8.9 FormRegistry 注册

新增表单组件后，需要在 `FormRegistry.ts` 中注册：

```typescript
// work/FormRegistry.ts
import { defineAsyncComponent } from 'vue'
import type { Component } from 'vue'

const formRegistry: Record<string, () => Promise<Component>> = {
  // 表单路径 → 组件
  'example_form': () => import('./forms/ExampleForm.vue'),
  'leave_form': () => import('./forms/LeaveForm.vue'),
  'expense_form': () => import('./forms/ExpenseForm.vue'),
}

export function getFormComponent(formPath: string): Component | null {
  const loader = formRegistry[formPath]
  if (loader) {
    return defineAsyncComponent(loader)
  }
  return null
}
```
