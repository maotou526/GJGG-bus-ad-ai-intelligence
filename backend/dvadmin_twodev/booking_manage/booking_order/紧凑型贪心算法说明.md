# 车位自动分配 - 紧凑型贪心算法 (Best-Fit Allocation)

## 算法目标

最大化资源利用率，通过优先选择"刚好够用"的车辆，保留长期空闲的车辆给未来的大订单。

## 核心思想

**"填满碎片时间，保留完整时段"**

- 优先分配那些在目标时间段前后都有订单的车辆（空闲时间被"夹"在中间）
- 次优分配那些只有前面或后面有订单的车辆（半开放空闲时间）
- 最后才分配完全空闲的车辆（保留给未来的长期订单）

## 算法流程

### 1. 预筛选阶段

```
输入: 线路ID, 媒体类型列表, 开始日期, 结束日期, 需要数量
输出: 可用车辆列表（按匹配分排序）
```

**步骤:**
1. 查询指定线路的所有可用车辆（`delete_mark=0`, `enabled_mark=1`）
2. 对每辆车检查所有基础类型资源位是否在目标时间段内可用
3. 使用时间段重叠检测排除冲突车辆

### 2. 匹配分计算 (`_calculate_fit_score`)

对每辆可用车辆计算"匹配分"（fit_score），规则如下:

#### 情况1: 目标时间段在两个订单之间（最优）
```
前订单: [====]
目标:          [------]
后订单:                  [====]

匹配分 = 空闲天数（前订单结束到后订单开始的总天数）
```
**示例:**
- 前订单结束: 2026-02-05
- 目标时间: 2026-02-10 ~ 2026-02-27
- 后订单开始: 2026-03-01
- 匹配分 = (2026-03-01 - 2026-02-05).days = 24天

**优先级: 最高** - 这种车辆的空闲时间刚好被利用，不会留下大的空档

#### 情况2: 只有前面或后面有订单（次优）
```
前订单: [====]
目标:          [------]
后面:                    （无订单）

或

前面:   （无订单）
目标:          [------]
后订单:                  [====]

匹配分 = 空闲天数 + 1000
```
**示例:**
- 只有前面有订单，结束于 2026-02-05
- 目标开始: 2026-02-10
- 匹配分 = (2026-02-10 - 2026-02-05).days + 1000 = 1005

**优先级: 中等** - 这种车辆有半开放的空闲时间，可以利用但不是最优

#### 情况3: 完全空闲（最差）
```
前面:   （无订单）
目标:          [------]
后面:                    （无订单）

匹配分 = 999999
```

**优先级: 最低** - 这种车辆完全空闲，保留给未来可能的长期订单

### 3. 排序与分配

```python
# 按匹配分从小到大排序
available_vehicles_with_score.sort(key=lambda x: x[1])

# 取前N辆车（N = 需要数量）
return sorted_vehicle_ids[:quantity]
```

## 算法优势

### 1. 资源利用率最大化
- 优先填满"碎片时间"，避免产生更多小的空闲时段
- 保留完整的长时间段给未来的大订单

### 2. 避免资源浪费
- 不会因为"先到先得"而占用长期空闲的优质车辆
- 减少因为碎片化导致的资源无法利用

### 3. 实时计算，无需预配置
- 根据当前实际订单情况动态计算匹配分
- 不需要人工配置权重或规则

## 示例场景

### 场景: 闵行10路，需要4辆车，左侧广告位，2026-02-10 ~ 2026-02-27

**候选车辆情况:**

| 车辆 | 前一个订单 | 后一个订单 | 匹配分 | 说明 |
|------|-----------|-----------|--------|------|
| 车A | 02-08结束 | 03-01开始 | 21天 | ✅ 最优：刚好填满空档 |
| 车B | 02-05结束 | 03-05开始 | 28天 | ✅ 次优：空档稍大 |
| 车C | 02-01结束 | 无 | 1009天 | ⚠️ 只有前面有订单 |
| 车D | 无 | 03-10开始 | 1011天 | ⚠️ 只有后面有订单 |
| 车E | 无 | 无 | 999999天 | ❌ 完全空闲，保留 |

**分配结果:**
- 选择: 车A, 车B, 车C, 车D
- 保留: 车E（给未来的长期订单）

## 技术实现

### 关键方法

1. **`_find_available_vehicles`**: 主入口，返回排序后的可用车辆列表
2. **`_calculate_fit_score`**: 计算单个车辆的匹配分
3. **时间段重叠检测**: 使用Django ORM的Q对象
   ```python
   Q(reserved_start_date__lte=end_date) &
   Q(reserved_end_date__gte=start_date)
   ```

### 数据库查询优化

- 使用 `order_by('reserved_start_date')` 预排序
- 使用 `filter().first()` 只取最近的一条记录
- 避免N+1查询，批量获取资源位信息

## 未来优化方向

### 1. 加权匹配分（如需更复杂的策略）
```python
fit_score = gap_days * weight_time + vehicle_priority * weight_priority
```

### 2. 线段树优化（大规模数据）
- 当车辆数量 > 1000 时，使用线段树加速时间段查询
- 可将查询复杂度从 O(n) 降到 O(log n)

### 3. 允许中途换车（区间覆盖问题）
- 将订单拆分为多个子时间段
- 每个子时间段分配不同车辆
- 需要评估线下执行成本（换广告贴纸）
